## Part 1. 계정관리 / 메뉴·DB 접근 권한 기능 (`DBAgent-Java`, 완료)

### 배경
기존엔 `admin` 계정 하나만 하드코딩되어 있었음. "일반 계정 생성 가능한가?"라는 질문에서 출발해서, role 기반 권한 + 계정별 메뉴 노출 + 계정별 DB 접근 제한까지 확장됨.

### 수정/신규 파일
**백엔드**
- `src/main/java/com/dbagent/auth/AuthService.java` — `users` 테이블에 `role`/`hidden_menus`/`hidden_dbs` 컬럼 추가(SQLite `ALTER TABLE ... ADD COLUMN`, 부팅 시 자동 마이그레이션), `AuthSession` 레코드, `canAccessDb()`, `createUser`/`updateUser`/`deleteUser`/`listUsers`
- `src/main/java/com/dbagent/auth/UserController.java`(신규) — `POST/GET/PUT/DELETE /api/users`
- `src/main/java/com/dbagent/auth/CreateUserRequest.java`, `UpdateUserRequest.java`(신규)
- `src/main/java/com/dbagent/auth/AuthController.java` — login/check-auth 응답에 `role`/`hidden_menus`/`hidden_dbs` 포함
- `src/main/java/com/dbagent/monitor/MonitorController.java` — `db_id` 받는 API 전부(tmlock/session/tablespace/dashboard/top_events/relation/session_query/table_info/failure_prob/history_sessions/health/history_top_sessions/db_users)에 `canAccessDb()` 체크 추가, `kill_session`은 기존 admin 체크 유지
- `src/main/java/com/dbagent/monitor/KillSessionRequest.java` — `token` 필드 추가
- `src/main/java/com/dbagent/query/SqlQueryController.java`, `SqlQueryRequest.java` — `execute`/`accounts`에 권한 체크 추가

**프런트엔드** (`index.html`, `app.js`, `style.css`)
- 우측 상단 톱니바퀴 → 드롭다운("계정 관리" / "메뉴 표시 설정")
- 계정 관리 모달: 목록 화면 ↔ 수정 화면 전환 구조 (인라인으로 안 붙임)
- 계정 생성/수정 시 "관리자(Admin) 권한 부여" 체크박스 1개 + "표시할 메뉴"/"접속 대상 DB" 체크박스 그리드 — 둘 다 화면에 이미 그려진 `.nav-item`/사이드바 DB 목록을 코드가 그대로 읽어서 만드는 방식이라, 나중에 메뉴나 DB가 추가돼도 코드 수정 없이 자동 반영됨
- `.menu-checkbox-grid` CSS 클래스 신설 (2열 그리드, `max-content` 컬럼폭 + `white-space: nowrap`으로 긴 라벨 줄바꿈 방지) — 처음엔 `.login-form-group input` 규칙이 체크박스에도 적용돼서 큰 사각형으로 깨졌던 버그를 수정하면서 도입
- 일반 계정은 SQL 실행/세션 Kill/장애조치/톱니바퀴가 `admin-only` 클래스로 숨겨지고, 서버단에서도 동일하게 막힘(브라우저 devtools로 직접 호출해도 403)

### 핵심 설계 원칙
- **확장 가능한 체크리스트**: 메뉴 목록도 DB 목록도 하드코딩이 아니라 DOM/사이드바에서 직접 읽어옴 → `index.html`에 메뉴 추가되거나 `databases.json`에 DB 추가되면 체크박스 목록에 자동으로 나타남
- **UI 숨김 ≠ 보안**: 메뉴/사이드바에서 숨기는 건 실수 방지용이고, 실제 권한 강제는 전부 서버단(`isAdmin()`, `canAccessDb()`)에서 함
- **admin 계정 보호**: `admin` 계정 자체는 삭제/역할변경 불가

### 검증 결과 (curl 기반, 이번 세션에서 전부 통과 확인)
- 일반 계정 생성 시 role/메뉴/DB 제한 지정 → 로그인 응답에 반영 확인
- 제한된 DB로 API 직접 호출 → 403 확인, 허용된 DB는 200
- 토큰 없이 호출 → 403 (부가효과로 이 API들이 원래 로그인 여부도 검증 안 하던 상태였는데 이번에 같이 막힘)
- admin 계정 삭제/역할변경 시도 → 거부 확인
- RAC처럼 한 그룹에 인스턴스가 여럿이고 일부만 허용한 경우도 그룹은 보이고 허용 안 한 인스턴스만 숨겨지는지 확인 (그룹 전체 숨김은 "그룹 내 전 인스턴스가 제한된 경우"만)

### 빌드/배포
- `.\build.ps1 -Dist`로 `dist\`까지 동기화 완료 (실행 정책 오류 시 `powershell -ExecutionPolicy Bypass -File .\build.ps1 -Dist` 또는 `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`)

## Part 2. AIX 서버 이관 (`DBAgent-Java-AIX`, 1단계 완료)

전체 배경/결정 근거는 `DBAgent-Java-AIX\AIX-DEPLOYMENT-REVIEW.md`에 있음 — 이 세션에서 그 문서도 갱신했으니 다음에 이어갈 때 그 파일부터 읽을 것.

### 확정된 결정
- **Java 8 + Spring Boot 2.7로 확정** (Java 17/Semeru 아님)
- 이유: AIX 서버가 정부 관리 센터 소속이라 OS 레벨 설치(XL C++ 업그레이드)를 임의로 못 함. 실측한 XL C++ 버전(`16.1.0.3`)이 Semeru 17 요구치(`16.1.0.10`)에는 못 미치지만, Java 8 요구치(`13.1.0.1`)는 이미 충족 → Java 8만이 센터에 아무것도 요청할 필요 없는 유일한 경로

### 1단계: Java 8/Spring Boot 2.7 언어 다운그레이드 — 완료
- **범위**: `AIX-DEPLOYMENT-REVIEW.md`가 원래 잡았던 것보다 컸음. 전수 조사 결과 `String.isBlank()`(22곳)/`strip()`/`stripTrailing()`(Java 11+)과 **`java.util.HexFormat`(Java 17+, 토큰 생성에 쓰고 있었음)**이 누락되어 있었음 — 이것들 없이는 Java 8 컴파일 자체가 안 됨
- `com.dbagent.util.{Maps, Lists, Strings}` 유틸 3개 신설해서 `Map.of`/`List.of`/`isBlank`/`strip`/`stripTrailing`/`HexFormat` 전부 드롭인 교체
- record 10개 → 일반 클래스 (접근자 메서드명 `token()` 스타일 그대로 유지해서 호출부 무변경)
- `jakarta.*` → `javax.*`, `var`/`instanceof` 패턴매칭 제거
- `ojdbc11` → `ojdbc8`, `pom.xml` parent `spring-boot-starter-parent` `2.7.18`
- Ollama 챗봇 기능 전체 제거 (`OllamaChatService.java`/`ChatRequest.java` 삭제, `/api/aidba/chat` 라우트 제거, 프런트 챗봇 탭 제거, 부수적으로 죽은 코드가 된 `ErrorSearchService`의 RAG 검색 메서드도 정리)
- **검증**: `<maven.compiler.release>8</maven.compiler.release>`로 JDK17 컴파일러가 Java 8 API 표면 기준 엄격 검사하도록 강제 → 컴파일 성공, 산출 클래스 파일 메이저 버전 **52(Java 8)** 확인. 로컬(`jdk17\bin\java`, 상위 호환 실행)로 기동 후 로그인/계정관리/SQL실행/세션Kill/에러검색 API 스모크 테스트 전부 통과, `/api/aidba/chat`은 404 확인

### 다음에 이어서 할 일 (2단계 이후, 순서대로)
1. **SQLite → H2 마이그레이션** — 아직 미착수. `users.db`(계정 정보, 새로 시작해도 무방 — admin 계정은 자동 부트스트랩됨)와 **`oracle_errors.db`(7.6MB, 실데이터 — 이건 실제로 옮겨야 함)** 두 개. 계획 초안(이전 계획 파일 참고):
   - `pom.xml`: `sqlite-jdbc` 제거, `com.h2database:h2:1.4.200` 추가 (Java 8이라 2.x 안 됨)
   - `application.properties`: `spring.datasource.url=jdbc:sqlite:users.db` → H2 file URL로 교체
   - `AuthService.init()`의 `PRAGMA table_info(users)` 컬럼 존재 체크 → H2는 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`를 네이티브 지원하므로 그걸로 단순화 가능
   - `ErrorSearchService.java`: `jdbc:sqlite:` → H2로 변경, 파일 존재 체크 로직도 H2 파일명 규칙(`.mv.db` 접미사)에 맞게 조정
   - `oracle_errors.db`의 `error_dictionary` 테이블 실데이터를, sqlite-jdbc가 아직 classpath에 있는 지금 시점에 (Java 소스 트리엔 이 테이블의 DDL/시드 스크립트가 없음 — 외부에서 만들어진 파일로 추정) 별도 일회성 마이그레이션 도구로 SQLite→H2 복사해야 함
2. `start.sh`/`stop.sh` 작성 (`start.ps1`/`stop.ps1`의 PID 파일 관리·포트 대기 로직을 ksh/bash로 이식)
3. `oracle.env`의 `ORACLE_HOME`을 AIX 서버 실제 경로로 수정 (사용자가 실제 값 제공 필요)
4. AIX용 **IBM SDK, Java Technology Edition 8** tar.gz 확보해서 `DBAgent-Java-AIX\jdk8\` 같은 이름으로 동봉 (다운로드는 IBM 사이트에서 사용자가 직접 받아야 함 — 이 환경에서 대신 받아줄 수 없음)
5. (선택) `dbagent.oracle.tns-admin` 등 배포 환경별 `application.properties` 오버라이드 준비

### 참고
- `DBAgent-Java-AIX`는 git 저장소 아님(이번 세션에 git init 안 하기로 결정) — 문제 생기면 `DBAgent-Java`(원본, Java 17/SB 3.3.5 그대로 유지 중)와 비교해서 수동 복구
- 로컬엔 Java 8 JDK가 따로 없음 — 컴파일 검증은 `maven.compiler.release=8`로, 실행 검증은 `jdk17`로 대신함 (상위 JVM은 하위 타깃 바이트코드를 항상 실행 가능). 실제 AIX Java 8 바이너리 자체의 최종 확인은 서버에서만 가능

## Part 3. 대시보드 UI 버그 수정 + 라이트 테마 신규 추가 + 로그인 화면 리디자인 (`DBAgent-Java`, 2026-08-25, 완료)

전부 프런트엔드(`src/main/resources/static/{index.html,app.js,style.css}`) 작업. 순서대로 진행하면서 뒤로 갈수록 앞 작업이 드러낸 더 근본적인 문제를 고치는 흐름이었음.

### 1. 대시보드 도넛 그래프가 DB 전환 시 초기화 안 되는 버그
- 증상: DB를 바꿔도 CPU/메모리/세션/실패율 도넛 차트가 새 데이터 오기 전까지 이전 DB 값(색상)을 그대로 표시
- 원인: `resetAllDashboardWidgets()`(`app.js`)가 텍스트값(`-`)만 리셋하고 Chart.js 도넛 인스턴스(`dashCpuChart`/`dashMemChart`/`dashSessChart`/`dashFailChart`)는 안 건드림
- 수정: `clearSegmentedDoughnutChart()` 헬퍼 신설 + `resetFailIndicator()` 신설, `resetBasic()`/`resetAllDashboardWidgets()`에서 호출

### 2. 라이트/다크 테마 토글 신규 기능
- 우측 상단 미사용 종(bell) 아이콘 → 테마 토글 아이콘(`#theme-toggle-btn`)으로 교체, 클릭 시 다크 ↔ 라이트, 선택값은 `localStorage('dbagent_theme')`에 저장
- `style.css`에 `:root[data-theme="light"]` 팔레트 블록 신설
- 토글 클릭 시 `location.reload()` — Chart.js 인스턴스들이 옵션을 생성 시점에 고정해서 쓰기 때문에, 개별 차트 옵션을 일일이 다시 주입하는 대신 새로고침으로 전부 새 테마로 다시 그리는 쪽을 택함

### 3. 라이트 테마에서 드러난 기존 버그들 (테마 작업이 아니었으면 발견 못 했을 것들)
- **Chart.js 하드코딩 흰색 문제**: 세션 추이/Trace scatter/AWR 히스토리 scatter/도넛 게이지의 눈금·격자선·테두리 색이 전부 흰색(`rgba(255,255,255,x)`)으로 박혀 있어서 라이트 테마에서 안 보임 → `chartLineColor(alpha)` 헬퍼(라이트는 짙은 남색, 다크는 흰색 반환)로 20곳 이상 교체
- **미정의 CSS 변수 대량 발견 (가장 큰 문제)**: SQL 실행/AI DBA/SQL 정합성·튜닝 패널 등 앱 곳곳(약 119곳)이 `--border-color`/`--text-secondary`/`--text-primary`/`--primary-color`/`--text-info`/`--bg-hover`를 쓰는데 `:root`에 **정의된 적이 없었음**. 다크 배경에선 우연히 안 티 났지만(테두리 없음=투명, 배경 없음=투명), 라이트 테마에서 "테두리 없이 하얗게 뜨고 클릭(포커스)해야 겨우 보이는" 증상으로 드러남 → `:root`에 6개 별칭 변수 추가(`--border-color: var(--border)` 등)로 한 번에 해결
- **막대그래프 트랙 vs 세그먼트 색 충돌**: 위 버그를 고치며 `--border`를 진하게 만들었더니, Active 세션 리스트의 Duration Time/Session Wait 막대가 트랙 배경으로 같은 변수를 재사용하고 있어서 Wait의 회색 "Other" 세그먼트와 톤이 겹쳐버림 → 막대 전용 `--track-bg` 변수 분리 + "Other" 세그먼트 색을 `var(--text-muted)`로 교체
- `.main-content` 우측 배경 그라데이션이 `rgba(30,41,59,0.8)`로 하드코딩돼 있던 것도 `var(--bg-panel)`로 교체(테마 연동)

### 4. 로그인 화면 리디자인
- 사용자가 제공한 레퍼런스 이미지 2장(퍼플 글로우 "SYNTH.AI" 스타일 → 이후 틸 글로우 "Musify" 스타일)을 스타일 참고용으로만 사용, 실제 입력창/버튼은 새로 HTML로 구현(이미지에 그려진 폼은 장식일 뿐이라 그대로는 동작 안 함)
- 최종 형태: 상단 브랜드 바 + 좌측 실제 로그인 폼(Username/Password/Sign in + 한국특허정보원 엠블럼) + 우측 대시보드 "미리보기" 카드(스탯 타일 4개 + SVG 추이곡선, 패널 밖으로 살짝 삐져나가 잘리는 연출, 760px 미만에서는 숨김)
- 배경/액센트 색은 최종적으로 임의 브랜드색(퍼플/틸)이 아니라 **실제 대시보드가 쓰는 다크 팔레트**로 통일: 배경은 `.main-content`와 동일한 `radial-gradient(circle at top right, #1e293b, #0f172a)`, 액센트는 `--primary`(#3b82f6), 미리보기 스탯 타일 4개는 `--primary`/`--success`/`--warning`/`--danger` 순
- `.login-card`/`.login-form-group`/`.login-btn`은 비밀번호 변경·계정관리 등 다른 모달에서도 공유하는 클래스라 건드리지 않고, `.login-showcase` 하위로 스코프를 새로 잡아서 로그인 화면에만 적용되게 함
- "Remember me"/"Forgot your password?"는 이 앱에 해당 기능이 없어서 제외(실제 동작하는 요소만 넣음)

### 배포 이슈 및 참고
- **`build.ps1 -Dist`에 잠재 버그 발견**: `dist\stop.ps1`을 `&`로 호출하면 그 안의 `Set-Location $PSScriptRoot`가 프로세스 전체의 현재 디렉터리를 `dist\`로 바꿔버려서, 이어지는 `Copy-Item $jar $distJar`가 `dist\target\...`(존재 안 함)를 찾다 실패함. 이번 세션엔 빌드→`dist\` 잡 수동 복사→`dist\start.ps1` 순으로 우회. **아직 미수정 상태로 남아있음** — 다음에 `-Dist` 옵션 쓸 일 있으면 먼저 고칠 것
- **실제로 브라우저가 붙는 인스턴스는 `target\`이 아니라 `dist\`**: 세션 시작 시점에 이미 `dist\`쪽 프로세스가 8006 포트를 점유 중이었음. `start.ps1`의 "포트 열림 = 기동 성공" 체크가 PID까지는 확인 안 해서, `target\` 인스턴스를 새로 띄워도 포트가 이미 열려있으면 성공으로 오판하고 실제로는 조용히 죽어버림 — 헷갈리기 쉬운 함정이니 배포 후 검증은 반드시 "서빙 중인 JS/CSS에 방금 바뀐 내용이 들어있는지" curl로 확인할 것
- 정적 리소스 캐시버스터(`index.html`의 `app.js?v=` / `style.css?v=`)를 이번 세션에 `app.js` v29→v32, `style.css` v5→v13까지 올림 — 앞으로 `app.js`/`style.css`를 고칠 때마다 버전 숫자를 반드시 올릴 것(안 올리면 브라우저가 캐시된 이전 버전을 계속 씀)
- 모든 변경은 `.\maven39\bin\mvn.cmd -q -DskipTests package`로 재빌드 후 `target\dbagent-java-0.1.0.jar`를 `dist\dbagent-java-0.1.0.jar`로 수동 동기화(`.bak` 백업 남김) → `dist\stop.ps1` → `dist\start.ps1` 순으로 반영. `JAVA_HOME`은 반드시 프로젝트 내 `jdk17\`로 지정([[build_environment]] 참고, PowerShell 세션 간 환경변수 안 남으므로 매 명령마다 재설정 필요)
