# SQL 정합성/튜닝 메뉴 신설 + 대시보드 개선 작업 정리 (2026-08-25)

오늘 세션은 `DBAgent-Java`(Java 17/Spring Boot 3.3.5, 원본)에 새 메뉴 하나("SQL 정합성/튜닝")와 대시보드 개선을 추가함. `DBAgent-Java-AIX`(Java 8 이관본)에는 아직 반영 안 됨 — 이 문서가 그 반영 작업의 체크리스트 역할.

**⚠️ 가장 먼저 볼 것: 맨 아래 "AIX 이관 시 필수 반영 사항" 섹션.** 오늘 추가한 코드에 Java 8/Spring Boot 2.7에서 그대로 안 돌아가는 문법이 다수 포함됨(record, `Map.of`, `String.isBlank/strip`, 그리고 특히 `java.net.http.HttpClient`).

---

## Part 1. SQL 정합성/튜닝 메뉴 신설 (신규 기능)

### 배경
별도 파인튜닝된 로컬 sLLM(Qwen2.5-Coder-7B + QLoRA 어댑터, `New_sLLM` 프로젝트)을 개인용 API로 서빙하고, `DBAgent-Java`에서 기존 "AI DBA"(Ollama 연동) 메뉴와 동일한 패턴으로 새 메뉴를 붙임 — merge 안 하고 base+어댑터를 그대로 얹어 서빙, DBAgent-Java는 그 서버를 HTTP로 호출만 함.

### 구성 요소

**추론 서버 (별도 프로젝트, 이 저장소 밖)**
- `New_sLLM/serve/api_server.py` — FastAPI, WSL에서 실행. 서버 시작 시 어댑터를 한 번만 로드해 메모리 상주, `POST /generate`로 응답. 포트 8010.
- **AIX 서버에는 WSL이 없음** — 이 부분은 이관 시 완전히 다른 방식으로 다시 설계해야 함 (아래 "AIX 이관" 섹션 참고).

**신규 백엔드 파일** (`src/main/java/com/dbagent/`)
- `sqltuning/SqlTuningController.java` — `/api/sqltuning/*` 엔드포인트 5개:
  - `POST /analyze` — 쿼리+실행계획 텍스트를 직접 받아 분석 (수동 입력 모드, 전체 사용자 가능)
  - `POST /analyze_from_query` — 쿼리만 받아 `EXPLAIN PLAN`으로 실행계획 조회 후 분석 (관리자 전용, 쿼리 미실행)
  - `POST /analyze_from_query_actual` — 쿼리를 실제 실행해 `DBMS_XPLAN.DISPLAY_CURSOR(ALLSTATS LAST)` 실측치로 분석 (관리자 전용, SELECT/WITH만 허용)
  - `POST /quick_check` — 위와 동일하게 실제 실행하지만 **sLLM 호출 없이** 실행계획/실측 통계만 바로 반환 (1차 성능점검용, 훨씬 빠름)
  - `POST /bind_capture` — `V$SQL_BIND_CAPTURE`에서 HASH_VALUE로 과거 바인드 값 조회 (일괄 입력용)
- `sqltuning/SqlTuningService.java` — FastAPI(`New_sLLM/serve/api_server.py`)를 HTTP로 호출 (기존 `OllamaChatService`와 동일 패턴)
- `sqltuning/SqlTuningRequest.java`, `SqlTuningAutoRequest.java`, `BindCaptureRequest.java` — 요청 DTO (전부 `record`)
- `query/ExecutionPlanService.java` — 핵심 로직. `EXPLAIN PLAN`/`DBMS_XPLAN.DISPLAY`(추정치, 미실행), `DBMS_XPLAN.DISPLAY_CURSOR`(실측치, 실제 실행) + `V$SQL` 기반 소요시간/CPU/Buffer Gets 요약, `V$SQL_BIND_CAPTURE` 조회, 쿼리 내 `:1`/`:SID` 형태 바인드 변수 자동 추출(`extractBindNames`, 정규식 `:([A-Za-z][A-Za-z0-9_$#]*|[0-9]+)`, 문자열 리터럴 내부는 제외)

**설정**
- `application.properties`: `sqltuning.api.url=http://localhost:8010` 추가

**프런트엔드** (`index.html`/`app.js`)
- 좌측 메뉴에 "SQL 정합성/튜닝" 신설
- 일반 사용자: 쿼리+실행계획 수동 입력 + "분석 실행"
- 관리자 전용 컨트롤(다 `admin-only` 클래스로 숨김, 서버단도 각 엔드포인트에서 `authService.isAdmin(token)`으로 재확인):
  - DB 접속 계정 선택 (`/api/query/accounts` 재사용)
  - "실행계획 조회 후 분석" (EXPLAIN PLAN)
  - "실제 실행 통계로 분석" (DISPLAY_CURSOR, 클릭 시 실행 확인 confirm)
  - "1차 성능점검" (AI 분석 없이 실행계획/실측 통계만, 클릭 시 확인 confirm)
  - "화면 클리어" (쿼리/바인드값/결과 초기화)
  - 바인드 변수 입력 패널: 쿼리 입력 중 실시간으로 `:1`류 바인드 변수 감지해서 입력칸 자동 생성. **6개 초과 시 자동으로 접히고 "펼치기" 토글 버튼** 등장(세로 스크롤 목록, `max-height: 320px`)
  - `V$SQL_BIND_CAPTURE`에서 HASH_VALUE로 일괄 불러오기 (바인드 이름이 쿼리의 것과 일치해야 채워짐)

### 트러블슈팅 (실제 겪은 오류, AIX 이관 시 동일하게 마주칠 수 있음)
- **`ORA-01780: 리터럴 문자열이 필요합니다`** — `EXPLAIN PLAN SET STATEMENT_ID = ?`처럼 바인드 변수(`?`)를 쓰면 발생. Oracle의 `EXPLAIN PLAN` 명령어 자체 문법이 `STATEMENT_ID` 자리에 **리터럴만** 허용하고 바인드 변수를 거부함. 해결: `PreparedStatement` 대신 `Statement`로 문자열을 직접 삽입(단, 값은 서버가 생성한 hex 문자열이라 인젝션 위험 없음).
- **`ORA-00972: 식별자의 길이가 너무 깁니다`** — `EXPLAIN PLAN`의 `STATEMENT_ID` 값이 30자를 넘으면 발생(데이터 길이 오류가 아니라 식별자 길이 규칙으로 취급됨, Oracle 내부 파서의 알려진 특성). 해결: STATEMENT_ID를 24자로 단축.

## Part 2. 대시보드 개선

### 2-1. 활성 세션 도넛 그래프 + 구간별 색상 + DB별 임계치
- **변경 전**: 헤더에 숫자만 표시, 그래프는 최근 5분 라인(sparkline) 차트, 색상 고정(초록)
- **변경 후**: CPU/메모리와 동일한 세그먼트 도넛(`createSegmentedDoughnutChart` 재사용) + 가운데에 세션 수 표시, 구간별 색상 적용
- **색상 구간(기본값)**: ~59 초록 / 60~69 노랑 / 70~79 주황 / 80~89 빨강 / 90~99 진한빨강 / 100+ 진한빨강(도넛 링 100% 고정, 숫자는 실제값)
- **DB별 임계치 커스터마이징**: `databases.json`의 인스턴스에 선택 필드 `"session_thresholds": [t1,t2,t3,t4,t5]` 추가 가능(없으면 기본값 `[60,70,80,90,100]`). **백엔드 코드 수정 불필요** — `DatabaseConfigService.safeConfig()`가 이미 `password` 제외 전 필드를 그대로 프런트에 넘기는 구조라, JSON에 필드만 추가하면 자동으로 `/api/config` 응답에 포함됨. 프런트(`app.js`)에서 DB 선택 시 `inst.session_thresholds`를 `window.currentSessionThresholds`에 저장해두고 `getSessColor(count, thresholds)`가 사용. 도넛 링 채움 비율도 고정 100이 아니라 `thresholds[4]`(그 DB의 최상위 임계치) 기준으로 스케일링.
- 현재 실제 적용값: "통합DB #1/#2"(`patent_integ_1`, `patent_integ_2`)에 `[80,90,100,110,120]` 설정, 나머지(검색DB/포탈)는 기본값.
- 삭제된 죽은 코드: `createSparkline()` 함수, `dashHistory.sess` 배열(더 이상 안 씀)

### 2-2. 화면 확대/축소 90% 기본값
- 요구사항: 최초 화면을 90%로 열고 이후 사용자가 자유롭게 조정 가능해야 함
- 구현: `<body>`가 아니라 `.app-container`(대시보드 콘텐츠 wrapper)에만 `style="zoom: 90%;"` 적용
- **버그 및 수정**: 처음엔 `<body>` 전체에 걸었더니 `#login-overlay`(`position: fixed; width: 100vw; height: 100vh`)가 줌 배율 계산에 영향을 받아 화면을 완전히 못 덮으면서 뒤의 대시보드가 비쳐 보이는 버그 발생 → 로그인 오버레이는 항상 100%로 유지되도록 줌 적용 범위를 `.app-container`로 좁혀서 해결. (CSS `zoom`은 비표준이지만 Chrome/Edge — 이 앱이 실제로 여는 브라우저 — 에서 동작. `position: fixed` + `vw`/`vh` 조합과 함께 쓸 때 이런 계산 어긋남이 생길 수 있다는 걸 기억해둘 것)

### 2-3. Caps Lock 경고
- 모든 비밀번호 입력란(로그인, 비밀번호 변경 3개, 신규 계정 생성 2개)에 Caps Lock 켜짐 경고 추가
- `attachCapsLockWarning(inputId, warningId)` 공용 함수, `keydown`/`keyup`에서 `event.getModifierState('CapsLock')` 체크

## AIX 이관 시 필수 반영 사항 (⚠️ 중요)

오늘 추가한 코드(주로 `sqltuning` 패키지, 일부 `query/ExecutionPlanService.java`)는 Java 17 기준으로 작성됨. `DBAgent-Java-AIX`(Java 8/Spring Boot 2.7)로 옮길 때 8/21 세션에서 확립한 패턴(`com.dbagent.util.{Maps,Lists,Strings}` 유틸 사용)을 그대로 따르면 되지만, 아래는 **새로 추가된 항목**이라 별도 확인 필요.

### 1. `record` → 일반 클래스 (기존 패턴 그대로 적용)
새로 생긴 record 3개, 8/21에 다른 10개를 바꿨던 것과 동일하게 처리:
- `SqlTuningRequest`, `SqlTuningAutoRequest`, `BindCaptureRequest`

### 2. `Map.of(...)` → `Maps.of(...)`
`SqlTuningController.java`에 20곳 이상 있음 (전부 `ResponseEntity.ok(Map.of(...))` 패턴). 8/21에 만든 `com.dbagent.util.Maps` 유틸로 기계적 치환 가능.

### 3. `String.isBlank()` → `Strings.isBlank(...)`
`SqlTuningController.java`, `SqlTuningService.java`에 다수. 8/21에 만든 `com.dbagent.util.Strings` 유틸 사용.

### 4. `String.strip()` / `.stripLeading()` / `.stripTrailing()` → `.trim()`
`ExecutionPlanService.java`에 3곳(`stripTrailingSemicolon` 메서드 등). `Strings` 유틸에 없다면 이번에 추가하거나, 이 파일에서는 그냥 `.trim()`으로 바꿔도 실질적으로 문제 없음(공백 종류 차이만 있고 이 용도엔 무관).

### 5. ⚠️ **`java.net.http.HttpClient` — 별도 설계 필요, 기계적 치환 불가**
`SqlTuningService.java`가 FastAPI 서버를 호출하는 데 `java.net.http.HttpClient`(Java 11+)를 씀. 이건 8/21에 지웠던 `OllamaChatService.java`도 원래 쓰던 것과 같은 API인데, 그때는 "Ollama 기능 자체를 통째로 제거"로 해결했었음(`AIX-DEPLOYMENT-REVIEW.md`/8-21 정리 문서 참고). 이번엔 SQL 정합성/튜닝이 핵심 신규 기능이라 **제거가 아니라 대체 구현이 필요**:
- 후보: Apache `HttpClient`(`org.apache.httpcomponents:httpclient`, pom에 추가 필요) 또는 순수 JDK `java.net.HttpURLConnection`(추가 의존성 없음, Java 8부터 있음, 다만 코드가 더 번거로움)
- 영향 범위: `SqlTuningService.analyze()` 메서드 하나뿐이라 교체 범위는 좁음

### 6. AIX 서버에서 sLLM(FastAPI) 서버를 어떻게 띄울지 — 아직 미검토
로컬 개발 환경은 WSL에서 `serve/api_server.py`를 돌리는데, **AIX 서버에는 WSL이 없음**. 다음 중 하나를 정해야 함:
- AIX 서버가 아닌 별도 Linux/GPU 서버에서 FastAPI를 띄우고, `sqltuning.api.url`을 그 서버 주소로 설정 (네트워크 경로 확보 필요)
- 아니면 이 기능 자체를 AIX 이관 1차 범위에서 제외하고 나중에 별도 검토
- (참고) 모델은 QLoRA 4bit 양자화라도 GPU가 필요함 — AIX 서버가 GPU 없는 POWER 서버라면 애초에 그 위에서 직접 돌리는 건 불가능

### 7. `databases.json`의 `session_thresholds` 필드
AIX 이관본의 `databases.json`(있다면 별도 파일/복사본일 가능성)에도 같은 필드를 넣어야 동일하게 동작함. `DatabaseConfigService.safeConfig()` 로직 자체는 이미 범용적이라 이 부분은 AIX 이관본에도 원래 있었다면 코드 수정 없이 데이터만 추가하면 됨(단, `pool_min_idle`/`pool_max_size` 대응 로직이 AIX 이관본에 이미 있는 걸 전제).

### 영향 없음 (프런트엔드 전부)
`index.html`/`app.js`/`style.css` 변경분은 정적 리소스라 Java 버전과 무관 — 그대로 복사하면 됨(단, 이 파일들이 AIX 이관본에서 얼마나 갈라졌는지에 따라 diff/병합 필요할 수 있음. 8/21 세션에서 Ollama 챗봇 탭을 프런트에서도 제거했다고 했으므로, `app.js`의 AI DBA 관련 코드 배치가 원본과 달라져 있을 가능성 있음 — 병합 시 그 부분 주의).
