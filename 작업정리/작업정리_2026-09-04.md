### 함정 — pull 직후 `mvn package`는 반영되지 않는다

`git pull`이 `src/main/resources/static/*`과 `target/classes/static/*`을 **같은 시각에 기록**하는데, maven-resources-plugin은 "source가 target보다 더 최신일 때만" 복사한다. 그래서 빌드 로그에 `Copying 25 resources`가 찍혀도 **옛 `target/classes` 파일이 그대로 jar에 들어간다.**

실제로 정적 파일 6개(app.js, index.html, fleet-overview.html, db-mgmt.html, mysql/postgres-overview-dashboard.html)가 옛 버전으로 배포됐다. `mvn clean package`로 해결.

**이후 모든 빌드는 `clean`을 붙였다.**

## 2. 환경 설정 파일 git 제외

`application.properties` / `oracle.env` / `databases.json`을 커밋·푸시 대상에서 제외 (회사 환경과 값이 달라 pull마다 충돌).

두 저장소 각 8개 파일에 `git update-index --skip-worktree` 적용:

```
application.properties        databases.json        oracle.env
dist/application.properties   dist/databases.json   dist/oracle.env
src/main/resources/application.properties
target/classes/application.properties
```

- 확인: `git ls-files -v | grep '^S '`
- **주의**: 원격에서 이 파일들이 바뀐 채 `git pull` 하면 "local changes would be overwritten" 에러. 해당 파일만 `--no-skip-worktree` → pull → 다시 설정.
- **주의**: `src/main/resources/application.properties`는 jar 내장 기본값(소스 성격)이라, 의도적 변경도 커밋되지 않는다.
- skip-worktree는 **이 PC 로컬 설정**. 회사 PC에는 적용 안 됨.

## 3. 로컬 Docker DB 환경 구축

`databases.json`의 비-Oracle 4종을 실제로 띄웠다.

| id | 컨테이너 | 포트 | 계정 | 상태 |
|---|---|---|---|---|
| `docker_mariadb` | `mariadb-dbagent` (mariadb:11.8.9) | 3306 | root/test | 신규 생성 |
| `docker_mysql` | `mysql-dbagent` (mysql:8.4.11) | 3307 | root/test | 신규 생성 |
| `docker_mssql` | `mssql-dbagent` (mssql/server:2022) | 1433 | sa/Test1234! | 신규 생성 |
| `docker_postgres` | `postgres16` (postgres:16.15) | 5432 | postgres/**postgres** | 기존 |
| Oracle | `oracle19c` (gvenzl/oracle-xe:21) | 1521 | dbagent_user/dbagent01 | 기존 |

신규 3종은 `--restart unless-stopped`.

### `databases.json` 수정 2건

1. **`docker_postgres` 비밀번호** `test` → `postgres` — 기존 컨테이너의 실제 값(`POSTGRES_PASSWORD=postgres`)과 달라 접속 실패했다. 컨테이너를 건드리지 않고 json을 맞췄다.
2. **`TEST01` 포트** 1522 → 1521 (정리 목적, 동작에는 영향 없음)

### Oracle은 수정 불필요 — `sid`가 SID가 아니라 TNS alias

`OracleConnectionPoolManager.buildDsn()`은 `host`가 비면 `sid`를 그대로 TNS alias로 쓴다(`jdbc:oracle:thin:@ORCL`). 이 PC의 `C:\oracle_docker_data\tnsnames.ora`에 `ORCL`~`ORCL10`이 전부 `127.0.0.1:1521 / SID=XE`로 정의되어 있어 이미 맞는 설정이었다. `host`가 비면 `port` 필드는 무시된다.

**반면 RDB 4종은 `host`가 필수다.** `RdbConnectionPoolManager.buildJdbcUrl()`이 폴백 없이 URL에 그대로 넣는다. `sid` 필드는 RDB에서 **데이터베이스 이름**을 뜻한다(MSSQL이 `master`인 이유).

### MariaDB 쿼리 호환성

`세션리스트 및 세션 정보 조회 쿼리.txt`의 세션 조회 쿼리가 **MariaDB에서 실패**한다.

```
ERROR 1146 (42S02): Table 'performance_schema.processlist' doesn't exist
```

| 객체 | MySQL 8.4 | MariaDB 11.8 |
|---|---|---|
| `performance_schema.processlist` | O | **X** |
| `performance_schema.data_lock_waits` / `data_locks` | O | X |
| `information_schema.PROCESSLIST` | O | O |
| `information_schema.INNODB_LOCKS` / `INNODB_LOCK_WAITS` | X (8.0에서 제거) | O |

**앱 코드는 문제없다.** `MySqlMonitorService.java:33`이 양쪽에 다 있는 `information_schema.processlist`를 쓴다. 문제는 참고용 txt 문서뿐이며, 정리한 md에 엔진별로 분기해 기록했다.

## 4. 화면 변경 — RDB 대시보드 (mssql / mysql / postgres × 2 프로젝트 = 6개 파일)

### 4-1. Fleet Overview 복귀 링크 제거
좌측 상단 `Fleet Overview로 돌아가기` 앵커 + `.back-link` CSS 삭제. 헤더의 `FO` 버튼과 브랜드 로고 링크는 유지.

### 4-2. 필터바 실동작화
기존 3개 항목이 전부 정적 목업이었고, **이 페이지엔 자동 새로고침 자체가 없었다**(로드 시 1회만 조회).

- **PMM Annotations 삭제** — 연동 대상(PMM 서버)이 없음
- **Interval** — 실제 폴링 구현. `auto (5s)` / `off` / `5s` / `10s` / `30s` / `1m` / `5m` / **`직접 입력`(1~3600초)**
  - `localStorage`에 선택값과 초 값을 따로 저장
  - 백그라운드 탭에서는 건너뜀(`document.hidden`)
  - 직접 입력은 `input`이 아닌 `change`로 받는다 — 타이핑 중간값마다 타이머를 재설정하면 1초 주기로 폭주
  - 범위 밖 입력은 잘라내고 입력칸 값도 보정
- **Host** — 가짜 호스트명(`ecy-s-dbrm-001`) → `/api/config`의 실제 `host:port`, 선택 시 해당 인스턴스로 이동

`auto`는 `/api/config`의 `polling_interval_ms`(2000)를 쓰지 않는다. 그 값은 오라클 메인 화면의 가벼운 폴링용이고, 이 대시보드는 한 사이클에 storage/sessions/overview/status를 여러 번 조회하므로 그대로 쓰면 DB에 과부하다.

### 4-3. 헤더 타이틀 드롭다운
`chevron-down`이 핸들러 없는 장식이었다. 인스턴스 전환 드롭다운으로 구현 — 그룹 헤더 + 인스턴스명 + `host:port`, 현재 인스턴스는 teal 강조 + 이동 불가, 바깥 클릭 시 닫힘. `/api/config`는 필터바가 받아둔 `cfg`를 재사용(추가 요청 없음).

### 4-4. 탭 정리
`Detail` 탭 제거, `Overview` → **`DASHBOARD`** + `layout-dashboard` 아이콘.

탭 버튼만 지우면 스크립트가 통째로 죽는다(`tabOverviewBtn`이 null → `classList`/`addEventListener`에서 TypeError). `showView()`와 클릭 핸들러를 함께 걷어내고 표시 상태만 고정했다. `overviewView` 마크업은 남겨두고 노출만 막았다.

글자색은 활성 시 `var(--blue)`, 크기 16px(오라클 화면 `.nav-item`과 동일 — 그쪽은 `font-size` 선언이 없어 브라우저 기본 16px).

### 4-5. 사이드바 상단 프레임
`한국특허정보원` 배지가 구분선 **아래**에 있어 별개 영역처럼 보였다. `.pmm-brand`가 자체 `border-bottom`을 갖고 있던 게 원인. `index.html`의 `.sidebar-header`와 같이 `.pmm-sidebar-header` 래퍼로 둘을 묶고 구분선을 래퍼로 옮겼다.

## 8. 브라우저 실렌더링 검증 (2026-09-05)

7절의 **"브라우저 실렌더링 미확인"** 항목을 해소했다.
