## 1. 배경 — 설계문서 검토 요청

Current Session 메뉴의 Active Session 차트를 개편하는 신규 설계문서 2건(회사에서 작성 후 집에서
일부 수정) 검토 요청. `design-advisor` 서브에이전트로 2회 검토:

1. 1차 — 메인 문서(§1~§9 전체 스펙) + 목업 HTML. Top-5 SQL 색상 재사용 원칙, gv$ 미사용 원칙과의
   충돌, 팔레트 충돌 가능성, 라이트 테마 전제 오류(이 앱은 흰 배경 자체가 없음), AWR 분모 보정
   누락 등 6가지 문제를 찾아 보고.
2. 2차 — 뒤늦게 발견된 참고 목업 파일(`active_session_mockup_1.html`, §1~§7 전용) 검토, 1차에서
   "구현 안 됨"으로 지적했던 6가지(텍스처 토글, 표 보기, KPI 행 등)가 실제로는 이 파일에 구현돼
   있음을 확인 — 진행 중 중지 요청으로 결과 일부만 받음.

## 2. §0 착수 전 결정사항 확정

design-advisor 검토에서 제기된 4가지 결정 필요 항목에 오케스트레이터가 직접 답변, 설계문서 §0로 반영:

1. **gv$ 미사용** — 2026-09-06에 확정된 "RAC라도 gv$ 안 쓴다" 원칙 유지, 접속 인스턴스(v$) 기준만.
2. **배치** — 기존 Current Session 2차트(추이 라인 + Trace 산점도)를 목업 화면으로 **완전 대체**.
3. **팔레트** — 그대로 유지. 확인해보니 §2의 7색이 이미 세션별 대기 분해 미니바(`app.js` waitHtml
   조립부)에서 쓰이던 색과 완전히 동일 — 신규 색 도입이 아니라 기존 색 재사용이었음이 밝혀짐.
4. **테마** — 라이트(흰) 배경 없음. `style.css`의 `data-theme="light"`도 실제로는 네이비 다크라,
   설계문서의 "라이트 모드 대비비 부족" 근거는 이 앱에 미적용 → 텍스처 토글 우선순위 하향.

## 3. 1단계 — Active Session Wait Class 차트

기존 좌측 "실시간 세션 추이" 라인 차트를 신규 차트로 완전 교체.

- 신규 `GET /api/ash_activity`(`MonitorService.getAshActivity`) — 7개 카테고리(CPU/Latch/User I/O/
  TX Lock/Sys I/O/TM Lock/Other) 시간 버킷 집계. FOREGROUND 필터, 모니터링 계정 제외, Idle 방어 반영.
  `cpu_cores`는 기존 v2가 쓰는 `v$osstat.NUM_CPUS` 재사용(화면마다 "코어 수"가 갈리는 문제 방지).
- **실측 버그 3건 발견·수정**(로컬 Docker Oracle로 실제 세션 발생시켜 검증하는 과정에서 전부 발견):
  1. `TIMESTAMP - TIMESTAMP`는 INTERVAL이라 NUMBER 연산 불가(`ORA-00932`) → `CAST(...AS DATE)`로 수정.
  2. `TO_CHAR` 포맷의 리터럴 `:00`에 따옴표 누락(`ORA-01821`) → `"00"`으로 인용.
  3. **가장 중요한 것** — 0-패딩 버킷 경계를 JVM 로컬시각으로 계산했는데 도커 컨테이너(UTC)와 앱
     서버(KST) 시간대가 달라 API가 항상 전부 0만 반환하던 버그. DB의 `SYSDATE`를 직접 읽어오도록
     수정 — 폐쇄망에서도 앱서버/DB서버 시간대가 다르면 재현될 수 있는 실질적 수정이었음.
- 죽은 코드 정리: 기존 `sessionHistory`/`TREND_SERIES`와 그 DB 전환 스냅샷 캐시를 깔끔히 제거.

## 4. 2단계 — 표현·접근성

- 영역형↔막대형 토글(전환 시 Chart.js 인스턴스 destroy 후 재생성), KPI 4종(현재 AAS+delta/CPU
  코어수/구간평균/기준선 초과비율, 전부 클라이언트 계산), 고대비 텍스처(CanvasPattern 45°/135°
  해치, 목업의 SVG `<pattern>` 방식을 canvas로 이식), 표로 보기 토글.

## 5. 3단계 — Top SQL Activity Timeline

- 신규 `GET /api/ash_top_sql` — Top5 SQL_ID + Other 누적. `FETCH FIRST` 대신 `ROWNUM`(코드베이스
  기존 관례 + Oracle 버전 미확정 대응). §8.1 팔레트 재사용 원칙 그대로 구현.
- 0-패딩 버킷 로직을 `generateAshBucketLabels()` 공유 헬퍼로 리팩토링(getAshActivity도 같이 정리 —
  3번째 복사본이 생기는 걸 방지).
- **후속 수정(오케스트레이터 요청)**: `label`을 SQL_ID 축약형("SQL-BU6BGF") 대신 카테고리명
  그대로("CPU"/"Latch" 등) 표시하도록 변경 — 동일 카테고리 SQL이 여럿이면 라벨이 중복될 수 있음을
  사용자에게 고지 완료.

## 6. 4단계 — 드래그 → 세션 상세, 기존 산점도 완전 대체

- **재사용 포기 결정**: 기존 `/api/history_sessions`는 "성능 이력 조회" 화면 전용으로
  `elapsed>=3초 AND exec_count>=100` 튜닝 후보 필터가 있어 일반 드래그 드릴다운엔 안 맞음(착수 전
  검토에서 발견) → 필터 없는 신규 `GET /api/ash_session_detail` 작성, `session-list.html`이 그대로
  기대하는 필드명으로 응답해 프론트 매핑 불필요하게 설계.
- 기존 Trace 산점도(`sessionScatterChart`, `SCATTER_CATEGORIES`, DB 전환 스냅샷 캐시 등) **완전
  제거**. `showSelectedSessionsPopup()`/`session-list.html`은 History 탭이 계속 쓰므로 그대로 유지.
- Top SQL 차트가 우측 패널로 이동 — 좌(Active Session)/우(Top SQL) 2단 레이아웃으로 최종 정리.

## 7. 5단계 — Other 드릴다운

- 신규 `GET /api/ash_other_breakdown`. Top5가 0~5개 가변 길이라 `NOT IN` 바인드 개수를 동적 생성
  (Top5 미만 시 바인드 불일치 버그를 원천 방어 — 빈 문자열로 보내는 극단 케이스까지 실측 검증).
- `SUM(cnt) OVER()`/`ROW_NUMBER()` 윈도우 함수로 랭킹과 "표시 안 된 나머지" 집계를 쿼리 1번에 처리.

## 8. 6단계 — 6시간/24시간 장기 구간 (자체 수집 경로)

착수 전 채팅으로 AWR 실시간 조회 vs 자체 수집 성능을 비교(이 코드베이스가 이미 겪은 v2 대시보드
커넥션 풀 고갈 사고를 근거로 제시) → **자체 수집 경로로 확정**.

- 기존 `instance_metric_history`(60초 샘플러)에 `metric_name` 8개(`ash_cpu`~`ash_other` 7개 +
  `ash_cpu_cores`) 추가 — **DDL 변경 0**. `getAshActivity()`와 완전히 같은 CASE 판정 기준을 그대로
  복사(두 경로가 같은 시간대를 다르게 분류하는 것 방지).
- 읽기는 신규 API 없이 기존 `GET /api/metric_history`에 `"6h"` range 케이스 1줄만 추가해 재사용.
- 프론트: 8개 시계열을 `sampledAt` 기준으로 병합해 기존 렌더러가 그대로 쓸 수 있는 모양으로 변환.
  Top SQL Activity Timeline은 6단계 범위 밖(SQL_ID 카디널리티 무한정)이라 장기 구간에서는 안내
  문구로 교체, 짧은 구간으로 돌아오면 완전히 복원됨을 확인.
- 쓰기량 기존 4개→12개(정확히 3배) — 로컬은 문제없었으나 인스턴스 많은 실제 폐쇄망에서는 체감
  여부를 지켜볼 필요 있다고 기록.

## 9. 실데이터 테스트 방법

전 단계에서 로컬 Docker Oracle(XE)에 별도 테스트 계정(`loadtest_app`, 모니터링 계정과 분리)으로
TX/TM Lock 대기, CPU 스핀 루프, 풀스캔(User I/O) 등을 직접 발생시켜 검증. Chrome 확장이 연결 안 돼
`browser-verification-via-cdp` 절차대로 로컬 Chrome을 `--remote-debugging-port`로 띄워 CDP로 직접
구동(드래그는 합성 마우스 이벤트로 재현, `window.open` 팝업 차단은 테스트 환경 한계로 별도 확인 —
localStorage에 올바른 데이터가 스택되는 것까지 검증해 실제 동작은 정상 판단).

## 10. code-inspector 점검 → 버그 1건 발견·수정

오늘 수정된 6개 파일(main/AIX 양쪽 12개) 전체를 `code-inspector` 서브에이전트로 점검.

- **[심각] 발견**: `getAshActivity()`의 `categoryKeys` 배열이 `"sys_io"`를 쓰는데, CASE 문은
  System I/O를 `"system_io"`로 분류 — 두 문자열이 안 맞아 **Sys I/O가 실시간(30분/1시간) 차트에서
  항상 0으로 표시**되고 있었음. 6단계 자체 수집 경로는 처음부터 `"system_io"`로 일관되게 작성해서
  이 버그의 영향이 없었음(우연히 맞았던 것).
- SQL 인젝션 점검(동적 바인드 처리), `monitoringAccountLiteral()` 복사 정확성, 프론트 오버레이
  패널 상태 관리, 8개 시계열 병합 로직, Java 8/AIX 포팅 문법 차이, 리소스 누수 — **전부 문제 없음**.
- `categoryKeys[4]`를 `"sys_io"→"system_io"`로 수정, main/AIX 동일 반영 + 재빌드·재기동 확인.
