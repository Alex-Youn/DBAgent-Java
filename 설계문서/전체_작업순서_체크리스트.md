## 순서를 정한 기준

1. **버그와 이미 결정된 작은 수정을 먼저** — 운영(폐쇄망)에서 바로 효과가 나고, 뒤 작업의 기준값(코어 수, 60초 기준)을 먼저 고정한다.
2. **화면 배율(4-1 90%→80%)을 화면 작업보다 먼저** — 대시보드 개편의 "1920×1040 스크롤 없음" 검증을 최종 배율로 한 번만 하기 위해서다.
3. **공통 기반을 한 번만 만든다** — 60초 샘플러 개선은 1-10(Current Session)과 대시보드 개편이 같이 쓰고, "ASH 구간 조회 + AWR 보충"은 대시보드 개편과 2번째(성능 분석)가 같이 쓴다. 따로 만들면 두 번 고치게 된다.
4. **공통 부품은 먼저 만드는 쪽에서 만들고 뒤에서 재사용** — 그래프 드래그(1-3 → 대시보드 ②), 스켈레톤·DB 전환 처리(1-2·1-5 → 대시보드), 세션 상세 팝업 스펙(4-3 → 4-2 팝업 통일 → 성능 분석 팝업).
5. **문서 작업은 코드가 안정된 뒤** — 쿼리 성능 체크 문서(5-2)와 산출물(8-1)은 마지막.

**모든 단계 공통**: 메인·AIX 동시 적용(AIX는 Java 8·H2), 단계마다 로컬 검증 → 커밋 → 작업정리 기록. `배포` 표시가 있는 곳에서 폐쇄망에 한 번씩 내보낸다.
