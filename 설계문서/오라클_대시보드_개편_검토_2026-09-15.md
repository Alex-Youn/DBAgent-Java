# 오라클 대시보드 개편 검토 (2026-09-15)

세션 중 대화로 진행한 설계 검토. 코드 변경은 아직 없음 - 방향/설계 확인 단계. [[최소Agent_적용검토_2026-09-15]]에서 이어지는 내용.

## 목적/범위

- **운영자가 대시보드 디자인을 직접 선택해서 운영**할 수 있게 하는 게 목적(사용자 요청, 2026-09-15).
- **기존 대시보드는 제거하지 않음** - 새 디자인을 추가하고 화면에서 선택 가능하게만 함.
- **범위는 오라클 전용** - `rdb-dashboard.html`이나 MySQL/MSSQL/PostgreSQL/CUBRID 쪽 `*-overview-dashboard.html`들은 이번 개편과 무관, **건드리지 않음**(사용자 확정, 2026-09-15). 참고로 오라클은 다른 DB 타입과 달리 별도 overview-dashboard 파일이 없고 `index.html`의 `<section id="dashboard">` 안에 직접 구현돼 있음.

## 선택 방식 - 화면 안 실시간 토글 버튼

- 운영자가 **대시보드 화면의 선택 버튼으로 신/구 디자인을 실시간 전환**할 수 있어야 함(재로그인/새로고침 불필요, 사용자 요청, 2026-09-15).
- 이 요구사항 때문에, `fleet-overview.html`/`fleet-overview-test.html`처럼 완전히 분리된 별도 페이지로 만드는 구조보다는 **`index.html`의 DASHBOARD 섹션 안에 신/구 두 버전을 같이 두고 버튼으로 display를 즉시 토글**하는 구조가 더 적합함. 이 앱에 이미 같은 성격의 선례가 있음:
  - 테마(palette 아이콘) 클릭 시 즉시 배색 전환 (`:root[data-theme]` 토글)
  - AI DBA 화면의 좌측 트리 메뉴/탭 전환 (`activateAidbaView`, `tunner-tab-btn` 클릭 시 즉시 섹션 전환)
  - 두 패턴 다 페이지 이동 없이 JS로 display만 바꾸는 방식 - 오라클 대시보드 선택 버튼도 같은 패턴 재사용 가능.
- 선택 상태를 세션/사용자 설정으로 기억해 둘지(로그인 응답의 `fleet_overview` 같은 사용자별 플래그 패턴 참고)는 미정 - 매번 기본값에서 시작할지, 마지막 선택을 기억할지는 추후 결정.

## Agent 데이터와의 관계

- Agent를 붙이면 새 대시보드에 표현할 수 있는 지표가 늘어남(Alert Log, tkprof, Clusterware 상태, OS 자원 등 - [[최소Agent_적용검토_2026-09-15]] 참고). 새 대시보드 디자인은 이 데이터들을 활용하는 것을 전제로 함.

## 진행 순서 (사용자 확정, 2026-09-15)

1. **Agent 프로그램 먼저 개발** - 최소 agent 스크립트 프로토타입(OS자원/alert log/tkprof 등)
2. **화면 1개만 만들어서 파일럿 테스트** - 전체 대시보드 개편에 들어가기 전에, agent가 보낸 데이터를 실제 화면 패널 하나에 붙여서 end-to-end로 먼저 검증
3. 파일럿이 검증되면 그다음에 **선택 가능한 대시보드 개편(실시간 토글 UI 포함)**으로 확장

즉 "대시보드 개편"보다 "**agent 파이프라인 검증**"이 먼저다 - 순서를 바꾸지 않도록 주의.
