# DB 모니터링 도구 – 로그인 후 첫 화면 설계안 (Fleet Overview)

## 1. 목적

로그인 후 첫 화면의 목적은 개별 DB의 상세 지표를 보여주는 것이 아니라, **관리 중인 여러 DB의 상태를 한눈에 스캔하고 문제가 있는 DB로 즉시 진입할 수 있게 하는 것**이다. 상세 실시간 모니터링(Active Session, Active Transaction, Lock Wait, Parallel Session, 2PC Pending Transaction 등의 시계열 차트)은 이 화면에서 DB 하나를 선택한 뒤 진입하는 다음 단계 화면이며, 첫 화면은 그 입구 역할을 한다.

관제 도구에서 흔히 쓰이는 "Fleet Overview" 패턴(Datadog Infrastructure, AWS RDS 콘솔, Oracle EM Fleet 화면 등)을 기반으로 구성했다.

## 2. 화면 구성

### 2.1 상단 요약 바 (Summary Bar)

전체 DB 개수와 상태별(정상/경고/위험) 개수를 스탯 타일로 표시한다. 로그인 직후 1~2초 안에 "지금 문제가 있는 DB가 있는지"를 파악할 수 있어야 한다는 요구를 충족하기 위한 영역이다.

- 전체 DB 수
- 정상 (녹색)
- 경고 (노랑/주황)
- 위험 (빨강)

### 2.2 DB 목록 – 카드형 / 테이블형

DB 개수에 따라 두 가지 뷰를 제공하고 토글로 전환한다.

- **카드형**: DB 수가 적을 때(8~10개 이하) 적합. 카드마다 DB명, 환경 태그, 상태 배지, 핵심 지표(Active Session, Lock Wait, CPU) 미니 표시, 마지막 업데이트 시각을 담는다.
- **테이블형**: DB 수가 많아질 때 적합. 컬럼은 상태, DB명, 환경, Active Session, Lock Wait, CPU, 업데이트 시각으로 구성하고 정렬·스캔이 카드보다 빠르다.

기본 정렬은 이름순이 아니라 **위험도순**(위험 → 경고 → 정상, 동순위 내에서는 CPU 높은 순)으로 고정한다. 문제가 있는 DB가 항상 목록 상단에 오도록 하기 위함이다.

### 2.3 검색 / 필터

- DB명 검색
- 환경 필터 (Production / Staging / Dev)
- 상태 필터 칩 (전체 / 위험 / 경고 / 정상)

DB 수가 늘어날수록 특정 그룹만 빠르게 좁혀볼 수 있어야 하므로 목록 상단에 항상 노출한다.

### 2.4 주의 필요 Top 5 (인사이트 패널)

우측 컬럼에는 실시간 알림 스트림 대신, 전체 DB 중 CPU 기준으로 위험도가 높은 상위 5개를 순위 목록으로 고정 배치한다. 검색/필터 상태와 무관하게 항상 전체 DB 기준으로 계산해서, DB 목록 쪽을 아무리 좁혀 봐도 우측 패널은 "지금 가장 신경 써야 할 DB"를 계속 보여준다. (알림 피드 방식은 검토했으나, 이벤트가 없을 때 패널이 비어 보이는 문제와 DB 목록 영역과 정보가 중복되는 문제가 있어 순위 목록으로 대체했다.)

### 2.5 목록 박스 크기

DB 목록 박스는 고정 높이를 두지 않고 콘텐츠(카드 또는 테이블 행 수) 만큼만 차지하도록 구성한다. 좌우 컬럼은 서로의 높이에 맞춰 늘어나지 않게(상단 정렬) 분리되어 있어, DB가 2~3개뿐이면 박스도 그만큼 작게, 수십 개면 그만큼 크게 자연스럽게 조정된다. 카드형 뷰에서는 카드 하나의 최대 너비도 제한해서, DB 수가 적어 한 줄이 다 안 채워져도 카드가 억지로 커지지 않고 원래 크기를 유지한 채 남는 공간은 여백으로 남긴다.

### 2.6 드릴다운

카드 또는 테이블 행을 클릭하면 해당 DB의 실시간 세션 모니터링 상세 화면(멀티라인 차트 + Lock Wait/2PC Pending 상태 카드)으로 이동한다. 즉 이 화면은 "요약 → 상세"로 이어지는 진입점이다.

## 3. 색상 규칙

### 3.1 배경

모니터링 도구의 대표 배경색인 `#0f172a`(네이비)를 기준으로 화면 전체를 고정 다크 테마로 구성한다(라이트 모드 없음). 카드·패널 등 중립 색상도 같은 네이비 계열(슬레이트 톤)로 맞춰서, 배경과 카드가 서로 다른 색 계열로 겉도는 것을 방지한다.

| 역할 | 색상 |
|---|---|
| 페이지 배경 | `#0f172a` |
| 카드/패널 배경 | `#1e293b` |
| 중첩/hover 배경 | `#24334a` |
| 기본 텍스트 | `#f1f5f9` |
| 보조 텍스트 | `#cbd5e1` |
| 흐린 텍스트 | `#94a3b8` |
| 구분선 | `#334155` |

### 3.2 상태색

| 용도 | 색상 | 비고 |
|---|---|---|
| 정상 | 녹색 (`#0ca30c`) | 상태 전용 색 – 다른 곳에 재사용하지 않음 |
| 경고 | 주황/노랑 (`#fab219`) | 상태 전용 색 |
| 위험 | 빨강 (`#d03b3b`) | 상태 전용 색 |

**중요:** 이 3색은 "DB 상태"만을 의미하는 전용 색으로 고정한다. 상세 화면에서 Active Session/Active Transaction/Parallel Session을 구분하는 데 쓰는 카테고리 색상(파랑/주황/아쿠아 등)과는 별개의 팔레트로 유지해야, 사용자가 화면을 이동했을 때 "이 색이 지표 구분색인지 상태 경고색인지" 혼동하지 않는다. 색만으로 상태를 전달하지 않도록 상태 배지에는 항상 텍스트 라벨(정상/경고/위험)을 함께 표기한다.

### 3.3 대비 검증

`#0f172a` 배경 기준 WCAG 명암비를 계산해 모든 색이 그래픽 요소 최소 기준(3:1) 이상, 텍스트는 4.5:1 이상을 만족하는지 확인했다.

| 색상 | 배경 대비 명암비 |
|---|---|
| 상태 정상 `#0ca30c` | 5.3:1 |
| 상태 경고 `#fab219` | 9.7:1 |
| 상태 위험 `#d03b3b` | 3.7:1 |
| 지표색(파랑) `#3987e5` | 4.9:1 |
| 보조 텍스트 `#cbd5e1` | 12.0:1 |
| 흐린 텍스트 `#94a3b8` | 7.0:1 |

## 4. 확장 시 고려사항

- DB 수가 수십~수백 개로 늘어나면 테이블형 뷰에 페이지네이션 또는 가상 스크롤을 적용한다.
- 그룹/태그 기반 필터(사업부, 서비스 단위 등)를 환경 필터 옆에 추가할 수 있다.
- 카드/테이블 어느 뷰에서도 정렬 기준(위험도순)은 사용자가 임의로 바꾸지 못하게 하거나, 바꾸더라도 기본값으로 쉽게 되돌릴 수 있게 한다 — 관제 화면의 핵심 목적(이상 탐지)을 해치지 않기 위함이다.
